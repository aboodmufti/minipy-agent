# AGENTS.md

Guidance for coding agents working in this repository.

## What this is

minipy is a Harbor agent harness. The model under test gets exactly one tool, `run_python`, and nothing else. That constraint is the point of the project, so changes must keep it. The repo also holds a benchmark for comparing harnesses and the scripts to run them.

## Layout

- `minipy_agent.py`: the whole harness (`MiniPyAgent`, a Harbor `BaseAgent`).
- `harnesses/pi_bearer.py`: Harbor's Pi agent with OAuth-token auth that keeps Pi in its normal mode.
- `scripts/run-harnesses.sh`: runs a Harbor task with minipy, Claude Code, mini-swe-agent and Pi.
- `benchmarks/tally/`: a single-task benchmark scored on quality and efficiency. See its README.
  - `src/original/` is the starting repository, `src/reference/` the reference solution's changes.
  - `grader/` holds the scoring code and the hidden tests.
  - `build.py` generates `task/`, which is not committed.
- `examples/svg-compare/`: a four-harness comparison on a 3D SVG task, with rendered results.

## Rules for changes to the harness

- **Keep one tool.** Do not add tools, shell access, file editors or a persistent interpreter for the model. Setup work the harness does itself (like installing `python3`) is fine, as long as the model never sees it as a tool.
- **Keep the history append-only.** Append each assistant response's `content` unchanged and never edit or drop earlier turns. Thinking blocks must be passed back as received.
- **Keep the model's view honest.** Tool results report the real exit code, stdout and stderr. When clipping, keep the head and tail and say how much was cut.
- **Keep it small.** The harness should stay readable in one sitting. Prefer removing code to adding options.
- **Use the Anthropic SDK** (`anthropic`), not raw HTTP. Keep streaming on, since responses can be long.

## Rules for changes to the benchmark

- **Standard library only** in `src/`, `grader/` and `report.py`. The task must run without network access or installs.
- **Keep the reference at 100.** After any change to `src/`, `grader/` or `template/`, run `python benchmarks/tally/build.py --check`. It must pass: reference about 100, starting code low.
- **Every mutant must be catchable.** A new mutant in `grader/mutants.py` needs a test in `src/reference/tests/test_recurring.py` that catches it, and its `old` text must appear exactly once.
- **Never edit `task/` by hand**; it is regenerated by `build.py`.
- **Don't leak the answers.** Nothing from `src/reference/`, `grader/hidden/` or `grader/mutants.py` may end up in `src/original/`, which the agent sees.

## Secrets

Never commit API keys, OAuth tokens or `.env` files. Pass credentials through environment variables, as `scripts/run-harnesses.sh` does.

## Checking a change

There is no separate unit test suite. Checks, cheapest first:

```bash
uv venv && uv pip install -e .
python -c "import minipy_agent"
python benchmarks/tally/build.py --check
harbor run -p examples/svg-compare/task -a minipy_agent:MiniPyAgent \
  -m anthropic/claude-opus-5-5 --ak effort=low --ak fallbacks=none -n 1 -y
```

The last command costs real API money; use one task at low effort for quick checks. A passing run writes `verifier/reward.json` or `reward.txt` and `agent/trajectory.jsonl` in the trial folder under `jobs/`.
